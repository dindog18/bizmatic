# Security and evidence-integrity findings

Scope: source review plus isolated synthetic tests, not a penetration test of a deployed service. No credential values, customer data, live endpoints or exploit traffic were used. Severity describes consequences if the application is reachable; external hosting restrictions were not inspected. See [issue register](mvp-gap-analysis.md) for related engineering risks.

## Pilot security gate

Complete B02–B08, B10, B23, B27–B28 before real customer access/data. A local development workspace may remain usable for synthetic work while these tasks are built. Use application authorization even when a private network is present. Restrict source connectivity to the known ERP network; read-only credentials alone do not bound the destinations the app can contact. Keep documents as untrusted data: embedded instructions must never trigger tool execution, connection changes or automatic finding approval.

TLS reasoning follows [PostgreSQL SSL documentation](https://www.postgresql.org/docs/18/libpq-ssl.html); production-setting checks follow the [Django deployment checklist](https://docs.djangoproject.com/en/6.0/howto/deployment/checklist/). No legal compliance certification or dependency CVE clearance is claimed.
