## Ten-step workflow

| Requested step | Status | Missing capability / completion criterion | Backlog |
| --- | --- | --- | --- |
| 1. Connect read-only PostgreSQL ERP | Partial | Current connector uses read-only options but accepts privileged accounts and arbitrary destinations; enforce admin-approved hosts, least privilege, identity-verifying TLS and restricted source grants | B02, B04–B06, B27 |
| 2. Inspect tables, columns, keys, relationships | Substantial code; integration unverified | Live isolated PostgreSQL tests; report metadata visibility limitations; schema fingerprint/drift checks; relationship meaning remains a human mapping decision | B01, B06, B12 |
| 3. Map ERP into AP/AR | Missing | Versioned canonical schemas, typed mappings, explicit joins and cardinality, preview, approval and rejection reasons | B11–B15, B29–B30 |
| 4. Structured PDF/scanned extraction | Partial text extraction only | Page OCR fallback, table/line reconstruction, typed schema validation, field evidence and reviewed revisions | B07–B10, B16–B17 |
| 5. Normalize and link | Missing | Exact source identities; counterparty/item aliases; dates/currency/UOM normalization; explicit and reviewed ambiguous links | B14–B15, B17–B18 |
| 6. Header/line PO/DR/SI reconciliation | Missing | Deterministic rules, price/tax basis, partial deliveries, line allocations, tolerance versioning | B19–B21 |
| 7. Missing/quantity/price/duplicate detection | Missing | Completeness-aware missing checks; quantity/price deltas; separate duplicate-import, duplicate-document and duplicate-transaction rules | B20–B22 |
| 8. Evidence and explanations | Partial original/Markdown comparison | Findings require exact source row, document revision/page/field, rule operands, expected/observed values and effect | B10, B17–B24 |
| 9. Approve/reject/investigate findings | Missing for findings | Existing document approval is a mutable flag. Add authorized actor, rationale, timestamp, investigate state, history and stale-review rejection | B05, B19, B23–B24 |
| 10. Audit report; no ERP changes | Missing report | Frozen manifest, scope/coverage/exceptions/findings/decisions, private download, reproducibility; no source mutation path | B25–B28 |

## Existing strengths to retain

Thin views delegate to services; Markdown rendering disables HTML/images; original URLs accept an ID rather than arbitrary browser paths; log and nested snapshot URLs check parent relationships; CSRF and method restrictions are tested. Document edits have revision conflict checks and writes use transactions/locks. Catalog extraction uses parameterized OID arrays, explicit read-only repeatable-read, query/lock timeouts and atomic local persistence. Credential encryption is separate from the app database, keys are permission-checked, fixtures cannot serialize decrypted passwords, and migration tests cover legacy password encryption. Preserve these protections while adding missing business boundaries.

## Practical scope

Do not build a general ERP, an arbitrary-SQL query console, autonomous accounting approvals, payments execution or ERP write-back. Begin with explicit mappings for one approved source and period; treat missing/ambiguous data as “cannot conclude,” not a clean audit. Supplier-specific identifiers, partial shipments, free units, discounts, VAT basis, returns and document-number reuse must be agreed with the business before rules are enabled. No VANS V2 schema or accounting convention was inferred from the app name.
